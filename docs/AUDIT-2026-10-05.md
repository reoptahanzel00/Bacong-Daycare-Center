# Final system audit — 2026-10-05

Scope: `main` at `cb91bc6`, the whole repository (API routes, auth, frontend views and
components, Supabase schema and migrations, document exports, CI). The fixes are on
branch `fix/final-audit-2026-10-05`. Three independent reviews (API/auth, frontend,
DB/exports/CI) were run, and every finding ranked High or above was re-checked against
the code before it was fixed.

## Verdict

**DEPLOY WITH NOTED RISKS** — once the migration below is applied.

The code was mechanically clean: typecheck, lint, both contract checks and the
E2E suite all passed. The real problems were the kind no static gate catches:
- saves that could wipe stored records;
- failures reported as success;
- report figures computed from data truncated at Supabase's 1000-row cap;
- a Next.js release with public unauthenticated RCE advisories.

All of these are fixed in code. Two things stand between this branch and a clean
**SAFE TO DEPLOY**:
1. `supabase/migrations/20261005_01_final_audit.sql` must be run on the live project
   (it closes F2).
2. The Supabase secret key that was pasted into an AI chat (tracker H2) is still the
   key in `.env.local`, and must be rotated.

## Findings and fixes

### CRITICAL

#### F1 — Next.js 15.5.23 with unauthenticated RCE advisories; jspdf 2.5.2 injection
- **Where:** `package.json`
- **Evidence:** `npm audit --omit=dev` listed:
  - `next` GHSA-p293-qw3h-jr36 and GHSA-2xp9-vwfh-vxw4 (critical);
  - `jspdf` up to 4.2.0 (critical), with `dompurify`;
  - `postcss` and `sharp` (high).
- **Fix:** `next@15.5.27`, `jspdf@4.2.1`, and npm `overrides` so Next's bundled
  `postcss`/`sharp` resolve to patched versions. Result: 0 vulnerabilities.

#### F2 — Disabled accounts kept full worker access at the database
- **Where:** `supabase/schema.sql` `current_user_role()`;
  `supabase/migrations/20260927_01_panel_revisions.sql:28`
- **What:**
  - `current_user_role()` returned the role of any profile, active or disabled.
  - The only status check lived in `/api/auth/login`.
  - The 20260927 migration turned every former official into a *disabled worker*
    without banning their login.
- **How it fails:** a former official signs in straight to Supabase with the public
  anon key. RLS then grants worker read and write on every child table.
- **Fix:** migration `20261005_01_final_audit.sql`, mirrored in `schema.sql`.
  - `current_user_role()` now requires `status = 'active'`.
  - Every disabled profile is banned at the auth layer.
  - `anon` loses execute on the function.

### HIGH

#### F3 — ECCD checklist could be permanently erased
- **Where:** `src/app/api/eccd/route.ts`, `src/views/WorkerView.tsx`
- **What:**
  - The GET used `.limit(5000)`, which Supabase silently caps at 1000 rows (about 10
    fully assessed children).
  - The POST deleted the round, then inserted.
  - The grid stayed saveable after a failed or in-flight load.
- **How it fails:** a truncated or failed load, then Save, sends all 109 items as
  "not present" and wipes the stored ticks. An insert error after the delete
  empties the round.
- **Fix:**
  - Paginated reads (`src/lib/supabase/paginate.ts`).
  - Insert-then-delete-by-id, and comments upserted on their primary key.
  - `domain_id` derived server-side from the fixed checklist.
  - Save disabled until the round has loaded, with an error state and Retry.
  - The grid clears on round change.
  - Scores are not saved when the ratings save fails.

#### F4 — Report figures computed from truncated data
- **Where:**
  - `src/app/api/reports/summary/route.ts` (`.limit(50000)`, capped at 1000);
  - `src/app/api/progress/stats/route.ts`;
  - `src/components/DSWDReportModal.tsx`, which used 500 attendance and 200 progress
    rows from the client;
  - the school-year selector, which filtered nothing.
- **Fix:**
  - All reads are paginated.
  - The summary accepts `?schoolYear=SY YYYY-YYYY`.
  - The DSWD modal prints server figures for the chosen year (ECCD-assessed uses the
    dashboard's definition), and its year list comes from the current date.

#### F5 — `schema.sql` could not build a fresh database
- **Where:** `supabase/schema.sql` — `center_settings` referenced `users` before
  `users` existed.
- **Fix:**
  - `center_settings` moved after `users`.
  - The settings row and the drifted index added.
  - The bucket definition aligned with its migration.

#### F6 — Failures reported as success
| Where | Before | After |
|---|---|---|
| `UserModal.tsx` | Network error added a fake `USR-xxxx` user, "Saved locally" | Error shown, modal stays open, nothing added |
| `DaycareContext.tsx` `handleToggleUserStatus` | API result ignored | List changes only on success |
| `DaycareContext.tsx` initial users and audit | Mock staff and audit rows shown in production | Empty until the server responds (mocks only in demo) |
| `api/pupils` POST | Guardian write errors logged, `success: true` | 500 with a clear message; unknown `id` returns 404 (no caller-chosen IDs, no skipped age check) |
| `api/auth/signup` | Stopped at the first failed child, still `linked: true` | Message and `childrenNotSaved` say how many were not saved |
| `ChildBackgroundModal` + `api/eccd/background` | Form seeded once (blank or another child's text), and the server nulled omitted fields | Remounted per child and per opening; worker loads the record before opening; partial update on the server; modal closes only on success |
| `PupilModal` | Closed before the save result | Closes only on success |
| `api/attendance/bulk` + register | Failed save left unsaved marks on screen | Rolled back; button disabled while saving |

### MEDIUM (all fixed)
- **Absence alerts:** they were re-sent on every register save. Now they are sent only
  when the save grows a streak past the threshold.
- **Register writes:** one row per pupil per save, and enrolled pupils only.
- **Approved excuse notes:** these were erased by the next register save. Notes are no
  longer sent from the register, and the server keeps the note on file.
- **Excuse decisions:** a malformed body counted as an approval. It is now a 400.
- **Account disabling:** a worker could disable their own account or the last active
  worker. Both are now blocked.
- **Linking parents:** `link-parent` silently re-pointed an already-linked guardian
  (now a 409), and orphaned an auth user when the profile insert failed (now rolled
  back).
- **Worker-issued password reset links:**
  - Before: the links never worked (implicit-flow tokens were sent to the PKCE
    callback), and the worker could get a sign-in link for any account.
  - Now: the link carries a `token_hash` that `/auth/callback` verifies. It is
    emailed when Resend is configured and issued for parent accounts only.
  - The UI copies the link instead of opening it, which would have replaced the
    worker's own session.
- **Parent portal:** switching children briefly showed the previous child's ECCD
  record and PDF. State is now tied to the child it belongs to.
- **Pupil detail:** the age was hard-coded as "4 yrs old", observation notes rendered
  blank, and the status badge always said "Enrolled". All three now show real data.
- **ProgressModal:** it fell back to the mock ID `PUP-2026-001` and allowed future
  dates. Both are fixed.
- **Double submits:** guarded on absence notes, account creation, reset links, the
  register, ECCD saves, the background form and the pupil form.
- **Temporary passwords:** generated with `crypto.getRandomValues` and a Fisher-Yates
  shuffle.
- **Login page:**
  - The hydration mismatch on `/login#create` is fixed.
  - "Account created!" no longer sticks after switching modes.
  - `?error=` / `?notice=` text is limited to messages the app sends.
- **Register date:**
  - Clearing the date is ignored.
  - A tab left open overnight no longer saves "today's" register under yesterday.
- **Raw database errors:** 16 routes returned them to the client. They are now logged
  server-side, and the client gets a generic message.
- **Word export:** XML-illegal control characters from pasted text broke the file.
  They are stripped now.
- **ECCD scaled score:** the API accepted 0–100. It now accepts 0–19, matching the
  form.
- **CI:**
  - The service-role key was exposed to every step, including `npm ci`. It is removed.
  - Node 20 (end of life 2026-10-01) is replaced by Node 22.
  - An `npm audit` gate is added.

## Recorded, not changed
- **Worker write RLS policies:** these let a worker write straight through the
  Supabase API, bypassing the audit trail. They are needed because the routes write
  with the user-scoped client. Moving those writes to the service role would let the
  policies go; that is a larger refactor.
- **CSP `script-src 'unsafe-inline'`:** moving to nonces is recommended but is a
  separate change.
- **Excused absences** still count toward the consecutive-absence streak. That is a
  product decision for the Daycare Worker.
- **Login limits:** login is rate-limited per IP only, with no per-account limit, and
  Student ID sign-in timing differs.
- **Dev-only advisories:** `braces` (no fixed version exists) in ESLint's tree. They
  are not shipped.
- **Partial scaled-score sums:** `sumOfScaledScores` prints a partial sum when not
  every domain is scored. This matches the existing tests and examiner workflow.
